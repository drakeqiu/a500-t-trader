# Compose 统一 Web 入口设计

状态：已讨论的部署设计，尚未实施。

## 目标与范围

使用 Compose 构建并启动前端容器，扩展现有 Nginx gateway，使其成为浏览器访问 UI 和业务 API 的唯一 Web 入口。支持本地开发、集成测试及单机网络部署，不引入第二个后端。

独立行情消费者仍可不启动 UI。RabbitMQ 等非 Web 接口及外部行情生产者的连接方式不在此次变更范围内。

## 请求路径

- Nginx 将 UI 请求代理到内部前端容器，前端不直接暴露主机端口。
- 业务 API 与 UI 使用同一个浏览器访问地址，对外 API 路径统一为 `/api/v1/...`。Nginx 根据现有业务路由将请求转发给对应后端。
- 迁移仓库内使用旧 API 入口或旧路径的调用方和文档，不保留旧的独立 API 主机入口或旧路径兼容层。
- 保持现有 API 认证和 SSE 流式传输行为；代理不得缓冲或提前中断正常的事件流。
- 身份提供方可以使用独立地址，不要求经过统一 Web 入口。

## Compose 与网络

- UI 和统一 Web 入口通过可选 Compose 配置启动，保留无需 UI 的独立行情消费者部署方式。完整应用提供明确的 Compose 启动命令。
- 入口默认只监听主机回环地址；需要其他设备访问时，由部署者显式配置监听地址。
- 部署时选择 HTTP 或 HTTPS 模式。HTTP 默认主机端口为 `8080`，HTTPS 默认主机端口为 `8443`，均可覆盖。
- HTTPS 模式不开放 HTTP。证书及私钥由部署者提供并只读挂载；替换证书后由部署者手动重载或重启 Nginx。
- HTTP 模式面向可信网络或由外部设施终止 TLS 的部署。在不可信网络上传输登录令牌时必须使用 HTTPS。

## 身份与前端配置

- 本地集成继续使用 Compose 中的 Keycloak，仅要求同机浏览器可访问；实际部署使用独立身份提供方。
- 保持身份提供方负责认证及签发令牌，业务 API 负责验证令牌的现有边界。
- 前端的公开配置在构建镜像时确定；不同环境可分别构建，issuer 等配置变化后需要重建前端镜像。

## 实施验收

1. 完整应用的 Compose 命令可构建并启动前端和统一入口；独立行情消费者仍可按原有用途启动。
2. 浏览器通过统一入口访问 UI 和 `/api/v1/...`；前端及旧 API gateway 不另行暴露主机入口。
3. HTTP 和 HTTPS 模式分别按配置工作，默认绑定回环地址，HTTPS 使用部署者提供的证书。
4. 本地 Keycloak 登录及受保护 API 请求正常；实际部署可配置独立身份提供方。
5. 信号 SSE 经统一入口持续流式传输；账户和信号 API 保持正确路由。
6. 更新受影响的调用方、部署文档和测试；执行相关单元测试、端到端测试及实际部署路径验证。
