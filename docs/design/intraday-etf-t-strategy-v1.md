# 场内 ETF 日内做 T 策略 V1.0 设计

## 状态

目标是由实时推送行情驱动的 V1 信号工具。当前实现与目标行为尚未完全对齐；此设计记录目标契约，不表示实时推送和 YAML 配置已经落地。规则来源是 [`docs/strategy/intraday-etf-t-v1/intraday_etf_t_quantitative_strategy_v1.0.md`](../strategy/intraday-etf-t-v1/intraday_etf_t_quantitative_strategy_v1.0.md)，本文不替代或修改该规则文件。

## 目标与边界

首版针对用户在配置中明确列出的 ETF，以已完成 5 分钟线计算 V1 信号；CLI 持续输出结构化结果，并保留策略 API。结果是非执行信号/建议，不是成交、收益承诺或券商账户证明。不连接券商、不发送委托。

V1 规则文件中的参数值作为默认值。可选 YAML 只覆盖 V1 已定义的参数，并明确列出目标 ETF；未覆盖参数使用规则默认值，未知参数或非法值拒绝加载。仓库提供默认配置路径，CLI 可覆盖该路径；无 YAML 时使用规则默认值。每份结果标识完整生效参数及稳定指纹。进程启动或显式重载时加载配置，运行期间不因文件变化自动切换参数。

实时推送按已完成 5 分钟线评估；相同策略身份和行情时点不重复输出。所需行情不足或过期时返回带原因的不可用/WAIT 状态，不生成方向或数量。建议数量仅在账户、交易规则、流动性等必要输入有效时给出，且不要求先通过历史回测认证。

## 输入与时间语义

- 每次计算使用 5 分钟已完成 K 线，需至少 180 根有效历史 K 线。未完成 5 分钟线不得参与确认；1 分钟推送不得替代 5 分钟确认。
- 指标：EMA(20)、EMA(60)、Bollinger(20, 2)、KDJ(9,3,3)、Wilder RSI(14)、Wilder ATR(14)、日内 VWAP（09:30 重置）。RSI 首个有效值由最初 14 个有效收盘价差初始化；缺值不得补成 50。
- 所有交易时刻按上海市场交易日历处理，不按普通工作日推断交易日。VWAP、冷却时间、盘中窗口及重置必须遵守源规则的交易时段定义。
- 09:45 VWAP 是网格锚点。缺少该锚点时不得用开盘价或后续 VWAP 替代；网格锚点缺失则相应策略建议不可用。
- 账户 NAV = 现金 + ETF 持仓当前市值。任何持仓无法取得有效、未过期行情估值时，不得计算可行动数量。

## 趋势与信号判定

趋势变量 `d=(EMA20−EMA60)/ATR`、`m=(EMA20_t−EMA20_(t−3))/ATR`：

| 状态        | 判定               | 约束                     |
| ----------- | ------------------ | ------------------------ |
| BULL        | d≥0.20 且 m≥0.05   | 普通规则                 |
| BEAR        | d≤−0.20 且 m≤−0.05 | 禁止普通 BUY             |
| RANGE       | 其他情况           | 普通规则                 |
| STRONG_BULL | d≥0.90 且 m≥0.25   | 强趋势子状态，不额外加分 |
| STRONG_BEAR | d≤−0.90 且 m≤−0.25 | 禁止 BUY 与 BUYBACK      |

买卖评分分别计算。权重为 EMA 20、Bollinger 20、KDJ 8、RSI 7、VWAP 25、动态网格 20；RSI 规则采用 Wilder(14)，30/70 参考线和 45/55 持续评分边界。KDJ 与 RSI 为共享的 15 分动量预算，不因 RSI 引入而改变总分或交易门槛。评分公式、边界和触发原因严格依策略源文件；候选阈值为 BUY≥72、SELL≥68、TAKE_PROFIT≥60、BUYBACK≥68，弱 BEAR 下 BUYBACK≥78，买卖差值门槛为 12。
普通 BUY/BUYBACK 还须当前 RSI>30 且较前一根上升；普通 SELL 须 RSI<70 且较前一根下降。缺少当前或前一根 RSI 时，普通交易不允许。TAKE_PROFIT 和强制风险退出不受 RSI 硬门槛否决，但 RSI 分项记 0 并报告缺失；其他退出条件仍须满足。RSI 不替代价格/KDJ 确认，不能单独产生交易。

## 规则身份与配置切换

RSI 修订后的目标规则仍来自 V1.0 策略源文件，但不等同于旧实现或旧回测结果。配置以 V1 规则文件为默认参数来源，允许 YAML 覆盖已定义参数；生效规则身份包括准确源文件 SHA-256、完整生效参数及实现版本。旧配置不得静默映射为新规则；具体配置 schema 和仓库默认路径须与实现一并确定。

旧配置若只绑定策略名称或旧源哈希，不能据此推断已采用 RSI 修订规则。未知参数、非法值或规则身份校验失败时拒绝加载。

配置与产品边界以 [ADR-0009](../adr/0009-live-signals-and-configurable-v1-parameters.md) 为准；历史 RSI 规则集切换背景见 [ADR-0008](../adr/0008-intraday-rsi-ruleset-and-config-cutover.md)。

`signal_strength` 表示技术规则评分（0–100），不表达成功概率。强制风险状态、阻断原因与评分分开呈现；风险阻断不得伪装成 100 分或改写技术分。

## 动态网格与交易状态

网格宽度由 ATR、交易成本和最小价位计算，受源规则上限约束（0.90%）；成本参数应按实际券商费用显式提供。示例费率不得当作账户默认值。网格在源文件规定的盘中检查时刻复核；变化达到 20% 时生成新 grid version。已闭合交易对保留原网格版本。

每网格层每轮只交易一次；同方向成交至少间隔 2 根已完成 5 分钟 bar；同方向冷却 10 分钟；网格穿越锚点连续两根已完成 bar 或新交易日时按规则重置。每日最多 3 次加仓、8 笔成交，日换手上限 150% NAV；普通卖出每日上限 10% NAV。单次意图数量不超过 NAV 的 8%，计划风险不超过 NAV 的 0.15%。其他间距、止盈、限频、止损和波动熔断按源文件完整规则实现，不简化为上述摘要。

既有持仓以用户确认的初始汇总快照建立：包括保护底仓、持仓/成本及可卖量；不合成历史策略交易对。仅底仓以上且实际可卖的数量可参与普通 SELL。策略激活后发生且明确关联到某条策略建议的实际成交才形成/完成策略交易对；未关联成交仅用于账本与账户对账，不自动配对或改变策略网格状态。

手工成交与 CSV 导入成交均只代表用户输入的已发生成交。用户必须显式将成交关联到策略建议；不包含未成交委托，也不自动猜测撮合关系。用户可用现金和股票持仓输入初始/更新账户状态；成交记录本身不自动改写现金或持仓快照。系统无法识别用户券商端未成交委托，因此有重复下单风险，建议结果必须明确提示这一限制。

## 账户风险与数量门控

- 单 ETF 资金预算：40% 目标底仓、25% 做 T 上限、35% 预留；实际最大持仓 65%、保护底仓 30%。这些比例按源规则作为显式策略配置，不从账户现有持仓反推或静默调整。
- 全组合总持仓不得超过 NAV 的 75%。组合评估按买入分数降序分配买入额度，分数相同时按证券代码升序；超出组合可用额度的标的返回 WAIT 并说明组合上限原因。

- 每证券独立数据异常/陈旧只阻断该证券；其他所需输入完整的证券仍可计算。缺失或过期账户快照时仍可输出技术分析，但状态为 WAIT，不返回许可数量。
- 每证券必需交易规则配置至少包括 T+0/T+1、最小交易单位/整手、最小价位；来源或更新时间无效即不输出行动数量。不得由 ETF 类别推断 T+0/T+1。
- 只有显式用户确认的实际成交才能更新交易状态。建议和模拟成交不得进入实时账户状态。

### `Q_capacity` 数量容量定义

`Q_capacity` 是当前账户状态下、该方向委托在仓位/库存约束内可接受的最大数量，不是固定手数。每次候选信号都用当时状态重新计算，并按证券整手向下取整。通用数量公式中的 `Q_capacity` 必须按方向解析：

```text
Q = lot_size × floor(min(Q_risk, Q_order, Q_capacity, Q_liquidity) / lot_size)
```

其中：

- `NAV = 账户总现金 + 持仓当前市值`；总现金包含冻结资金，仓位市值使用该候选时点的有效价格，不使用持仓成本价代替。
- `Q_order = 8% × NAV / P`，遵循 V1 单笔委托上限。
- `Q_liquidity` 遵循源规则的最近已完成 5 分钟成交量参与率上限。
- 限额数量计算中扣除已冻结现金、未完成买单的资金预留，以及已占用相应仓位/每日限额的未完成委托，避免重复分配额度。

#### SELL 容量

普通卖出可用容量：

```text
sellable_above_floor =
    max(0, min(当前可卖数量, 当前持仓数量 - protected_floor))
Q_capacity_sell = min(
    sellable_above_floor,
    floor_lot(剩余普通卖出日额度 / P)
)
```

如卖出属于配对止盈/回补状态，还须限制为对应未平配对数量。T+1 新买入份额不计入当前可卖数量。风险强制卖出可按策略规则绕过普通每日卖出额度；是否允许突破用户明确的 `protected_floor` 必须是独立显式配置。缺省不允许突破保护底仓。

#### BUY 容量

```text
total_position_room = max(0, 65% × NAV - 当前持仓市值)
cash_room = max(0, 账户总现金 - 35% × NAV - 已冻结现金)
trading_position = max(0, 当前持仓数量 - protected_floor) × P
trading_room = max(0, 25% × NAV - trading_position)

Q_capacity_buy = min(
    floor_lot(total_position_room / P),
    floor_lot(cash_room / P),
    floor_lot(trading_room / P)
)
```

买入资金可负担性须再按实际费用精确校验：佣金取比例费与每笔最低佣金的较大值；若因费用后现金不足，按整手递减到可成交数量。BUYBACK 还需将容量限制在尚未买回的关联配对卖出数量内。若最终数量不足一手，则返回 WAIT，不生成委托。

#### 用户指定的保护底仓

账户配置的显式 `protected_floor` 优先于 V1 通用 30% NAV 底仓下限；不得将两者混为一个比例。本次回测起始账户按用户确认为空仓，因此基于初始持仓的 70% 保护份额为 0：

```text
protected_floor = ceil(0 × 70% / 100) × 100 = 0 份
```

历史记录中曾出现 400,700 份持仓及 280,500 份保护底仓；该旧快照日期早于 563360 上市，且与本次用户指定的回测起始状态不一致，不得用于本次回放。后续买入份额是否受 70% 保护及其重算口径，须按策略规则明确实现。

#### 状态与可复现性

回测数量解析器须读取每根历史 bar 时点的现金、持仓、可卖库存、保护底仓、冻结现金、未完成委托、当日成交额/限额及配对账本。每次分配容量后，订单提交/成交/撤销应更新后续候选的可用状态；否则同一额度可能被多次使用。账户或证券规则缺失、价格/估值无效时，数量为不可用并返回 WAIT，不能回退到固定数量。

## 流动性、成本和可交易性

严格应用源文件的流动性过滤：20 日平均日成交额至少 3000 万元、最近已完成 5 分钟成交额至少 100 万元、买卖价差不超过 `max(0.15%, 2*tick/P)`、意图量不超过该 5 分钟成交量的 2%、ATR/P 在 0.08%–1.50%，并满足 180 根有效 bar。失败则禁止新交易；风险退出仍受实际可交易条件约束。所需行情字段不存在/陈旧时按失败处理，不做代理替代。

成本模型包含逐笔双边费用和冲击成本；策略文件所列佣金/冲击示例只是示例。每个账户需配置实际佣金、最低费用及冲击假设；缺少费用输入时不能宣称净利润或通过回测认证。止盈需覆盖成本并遵循源文件的 `max(g, 3bP)` 等确切规则。

## 历史回放与认证边界

历史回放是可选的观察/研究能力，不是实时信号或建议数量的资格门槛。回放和认证结果必须绑定各自的策略身份、数据快照、成本及执行假设；不能将历史结果表述为未来收益保证。V1 源文件中的回测验证要求仍可用于研究评估，但未完成这些研究项目不阻断实时信号。

如进行严格研究，源规则列出的评估包括扣费后收益、配对交易净利、Profit Factor、样本内外表现、最大回撤、样本量、成本压力、邻近参数稳定性及 walk-forward。历史撮合还应区分信号时点与下一可成交时点，模拟部分成交/撤单、资金预留、费用、库存及 T+1。这里描述的是研究方法，不是产品启用门槛。

已有固定份额技术候选回放保留为历史研究材料，不代表完整账户执行回放。其数据覆盖、账户输入及缺失项详见 [`docs/backtest-563360-v1.md`](../backtest-563360-v1.md)；不得把研究模拟状态说成券商账户证明或认证。

## 输出契约

策略结果至少包含：`signal`（方向/状态、技术分、规则依据、确认时间）、`position`（如有输入则提供账户估值及约束）、`execution`（是否允许、建议数量、参考信息及失效时间）、`risk`（阻断项与限制）、`reasons`（逐项依据）、`effective_parameters` 与其稳定指纹。输入不足或过期时不生成方向或数量；信号不表示订单或真实成交。CLI 仅编排 API 并呈现结果，不在 CLI 内复制策略计算逻辑。

## 验收边界与待实现

实现与测试应逐条覆盖源文件中的公式、阈值、时段、限额和状态转移，并验证边界值、缺失/陈旧数据及数量约束。历史认证失效不影响实时信号资格；实际可行动数量仍须满足有效账户、证券规则、行情及风险输入。
