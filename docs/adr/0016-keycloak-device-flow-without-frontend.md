# Use Keycloak device authorization without an application frontend

The browser client and its Authorization Code with PKCE flow from ADR-0015 are superseded: the project will provide no bundled browser frontend, CLI, or SDK, and callers will obtain tokens directly from the trusted OIDC provider using OAuth 2.0 Device Authorization Flow. Keycloak is the Compose-managed provider for local and test environments, with its data persisted in a named volume; production may use an externally managed Keycloak instance. A reproducible realm configuration will enable a public client for device authorization and issue access tokens for the shared `a500-api` audience, without committing client secrets or default users. Administrators provision permitted users in Keycloak; self-registration remains disabled. A500 APIs only validate IdP-issued Bearer access tokens and identify account ownership by verified `sub`; they do not expose login routes, validate passwords, issue tokens, or refresh them. Token lifetime and refresh policy belong to Keycloak, and callers are responsible for safely storing and refreshing tokens.
